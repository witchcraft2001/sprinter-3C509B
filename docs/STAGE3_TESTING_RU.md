# Этап 3: протокол проверки 3C509B

Эта инструкция описывает только сбор evidence. Она не означает, что проверки
уже выполнены. До появления фактических логов и снимков пункты MAME и реального
Sprinter в `specs.md` остаются открытыми.

Проверка этапа 3 не требует сети, pcap или IRQ. EEPROM доступна только для
чтения. Не подключайте `irq*_callback` карты к CPU Sprinter и не выбирайте
сетевой provider MAME.

## 1. Подготовка образа и каталога evidence

Из корня репозитория выполните:

```sh
make clean
make build
make test-host
make package
make image
sha256sum build/EL3INFO.EXE build/EL3EEP.EXE build/ISAPROBE.EXE \
  distr/sprinter-3c509b.img distr/sprinter-3c509b.zip
```

На macOS вместо `sha256sum` используйте `shasum -a 256`. Все команды сборки
должны завершиться успешно. Сохраните полный вывод и хеши в bundle:

```text
docs/evidence/stage03-YYYYMMDD-mame/
docs/evidence/stage03-YYYYMMDD-hw/
```

Для каждого bundle заполните копию
`docs/evidence/STAGE3_TEST_TEMPLATE.md`. Не заменяйте существующий bundle:
новый прогон получает новую дату или суффикс `-02`, `-03`.

Для MAME зафиксируйте:

```sh
MAME_BIN="../mame_images/mame_release_v306_25.05.2025/mame"
"$MAME_BIN" -version
git -C ../mame rev-parse HEAD
```

Ожидаемый baseline: MAME `0.287` (LP64), исходники commit
`cd34cb6a94434e15270550102ad94798f7650621`, DSS `1.71.64`, программы
`0.0.1`. Если версия или commit отличаются, продолжать можно, но отличие надо
явно записать; такой прогон не подтверждает именно заявленный baseline.

## 2. Как запускать MAME

Неизменённый MAME запускается локальным скриптом. Карта должна работать в
режиме `Real (ID sequence required)`.

```sh
MAME_3C509B_SLOT=0 tools/3com.sh
MAME_3C509B_SLOT=1 tools/3com.sh
```

Значение по умолчанию — slot 1. В slot 1 launcher оставляет NeoGS в slot 0; в
slot 0 ставит туда 3C509B. Скрипт не меняет исходники MAME, конфигурацию сети
или IRQ-маршрутизацию.

Для проверки отсутствующей карты используйте тот же профиль, но исключите
только тестируемую 3C509B:

```sh
MAME_3C509B_SLOT=0 MAME_3C509B_CARD=absent tools/3com.sh
MAME_3C509B_SLOT=1 MAME_3C509B_CARD=absent tools/3com.sh
```

После загрузки DSS перейдите на диск с образом этапа 3 и запускайте команды из
следующей матрицы. Между прогонами с разными slot или состоянием карты полностью
закрывайте MAME. Между разными `-b` достаточно нового запуска `EL3INFO`: команда
делает reset/discovery и задаёт только временную runtime-базу.

## 3. Обязательная матрица MAME

Для каждой строки сохраните введённую команду, весь видимый вывод, итоговую
строку результата и снимок экрана.

| ID | Slot | Команда DSS | Что должно быть подтверждено |
|---|---:|---|---|
| M01 | 0 | `EL3INFO -v -s 0 -p #110 -b AUTO` | карта найдена, EEPROM-база и расширенные поля напечатаны, `RESULT OK` |
| M02 | 1 | `EL3INFO -v -s 1 -p #110 -b AUTO` | то же для второго ISA-слота |
| M03 | 0 | `EL3INFO -s 0 -p #110 -b #200` | временная база `0200`, `RESULT OK` |
| M04 | 0 | `EL3INFO -s 0 -p #110 -b #300` | временная база `0300`, `RESULT OK` |
| M05 | 0 | `EL3INFO -s 0 -p #110 -b #3E0` | временная база `03E0`, `RESULT OK` |
| M06 | 1 | `EL3INFO -s 1 -p #110 -b #200` | временная база `0200`, `RESULT OK` |
| M07 | 1 | `EL3INFO -s 1 -p #110 -b #300` | временная база `0300`, `RESULT OK` |
| M08 | 1 | `EL3INFO -s 1 -p #110 -b #3E0` | временная база `03E0`, `RESULT OK` |
| M09 | 0 | `EL3INFO -s 0 -p #110 -b AUTO` при `MAME_3C509B_CARD=absent` | конечный отказ, без зависания |
| M10 | 1 | `EL3INFO -s 1 -p #110 -b AUTO` при `MAME_3C509B_CARD=absent` | конечный отказ, без зависания |
| M11 | 1 | `EL3INFO -s 2` | справка, `RESULT FAIL code=2`; обращений к ISA быть не должно |
| M12 | 1 | `EL3INFO -p #101` | справка, `RESULT FAIL code=2`; ID-порт не выровнен |
| M13 | 1 | `EL3INFO -p #200` | справка, `RESULT FAIL code=2`; ID-порт вне диапазона |
| M14 | 1 | `EL3INFO -b #3F0` | справка, `RESULT FAIL code=2`; база вне диапазона |
| M15 | 1 | `EL3INFO -h` | справка и `RESULT OK`; обращений к ISA быть не должно |
| M16 | 1 | `ISAPROBE` | только справка и `RESULT FAIL code=2`; обращений к ISA быть не должно |
| M17 | 1 | `EL3EEP -s 1 -p #110` | все 64 слова `00..3F`, валидация и `RESULT OK` |

Другой допустимый выровненный ID-порт (`#100`, `#120`, ..., `#1F0`) не является
отрицательным тестом: два selector-записывания могут законно перевести classic
3C509B на выбранный порт. Отрицательные CLI-тесты используют только
невыровненное или выходящее за диапазон значение и должны завершиться до
открытия ISA-окна.

`ISAPROBE` не нужен для обнаружения карты. Если требуется отдельно подтвердить
сам механизм явно ограниченного чтения, используйте только заранее известный
безопасный диапазон, например после успешной активации в том же slot:

```text
ISAPROBE -s 1 -b #0300 -n #0010
```

Ожидаются строка `[E0] SLOT=1 BASE=0300 COUNT=0010`, одна строка `[E6]` с 16
байтами и `RESULT OK`. Не расширяйте диапазон и не сканируйте неизвестные ISA
адреса: даже чтение чужого устройства может иметь побочный эффект.

## 4. Ожидаемый вывод и критерии PASS/FAIL

Успешный `EL3INFO` имеет такой каркас:

```text
3C509B EL3INFO v0.0.1
[E0] SLOT=1 IDPORT=0110
[E1] PRODUCT=9550 IO=0300
[E2] MAC=xx:xx:xx:xx:xx:xx
[E3] IRQ=n (not used by Sprinter)
RESULT OK
```

В режиме `-v` перед итогом добавляются:

```text
[E4] MFG=6D50 ADDR=xxxx RESOURCE=xxxx
[E5] CHECKSUM=xxxx SECONDARY=xxxx
```

Не подставляйте ожидаемый MAC заранее: перепишите ровно то, что показала
конкретная карта/слот, а затем сравните байты с EEPROM. Поле IRQ только
информационное; оно не должно использоваться Sprinter.

Успешный `EL3EEP` печатает:

```text
3C509B EL3EEP v0.0.1
[E0] SLOT=1 IDPORT=0110
[E1] EEPROM WORDS 00..3F
00: xxxx
...
3F: xxxx
[E2] IDS MAC CHECKSUMS VALID
RESULT OK
```

PASS для dump означает, что присутствуют все адреса `00`–`3F` ровно по одному,
слово `03` равно `9550`, слово `07` равно `6D50`, MAC в словах `00`–`02`
совпадает с `[E2] MAC`, а обе проверки checksum завершились строкой `[E2]`.
При преобразовании EEPROM-слов берите сначала младший, затем старший байт:
например, label MAC `00:20:AF:5D:69:8B` соответствует напечатанным словам
`00: 2000`, `01: 5DAF`, `02: 8B69`.

При отсутствующей карте ожидается конечный `RESULT FAIL code=3`. Допустима
другая явная конечная ошибка, если она отражает обнаруженное расхождение MAME,
но такой прогон считается FAIL и значение нельзя исправлять в отчёте. Предел
100 мс относится к одному ожиданию; чтение 64 слов с обязательными паузами
занимает несколько секунд. Для практической ручной проверки остановите прогон,
если DSS не вернул управление за 10 секунд, и запишите это как timeout/hang с
видео.

Коды результата:

| Код | Значение |
|---:|---|
| 0 | успех |
| 1 | ошибка формы команды (зарезервировано) |
| 2 | неверный параметр |
| 3 | карта/ID не найдены |
| 4 | конечный timer timeout; `ticks` — число оборотов CTC0 (около 2,47 мс) |
| 5 | checksum EEPROM |
| 6 | I/O-база |
| 7 | проверка активного окна |
| 8 | состояние ISA-окна |

Нельзя считать успешным прогон без финальной строки `RESULT OK`. Не
перезапускайте неудачный тест до сохранения его точного вывода и условий.

## 5. Какие снимки и дампы сохранить

Для снимка сначала нажмите Left Ctrl+Delete: это исходная комбинация данного
комплекта MAME для переключения между клавиатурой Sprinter и командами
интерфейса MAME. Затем нажмите F12 (на macOS может понадобиться Fn+F12): MAME
сохранит PNG в каталоге `snap`. После снимка снова нажмите Left Ctrl+Delete,
чтобы ввод вернулся в Sprinter. Сразу перенесите PNG в bundle и дайте ему имя
по ID матрицы, например:

```text
M01-slot0-auto.png
M03-slot0-base0200.png
M09-slot0-absent.png
M17-eeprom-start.png
M17-eeprom-end.png
```

Для M01–M16 достаточно одного снимка, если на нём одновременно видны введённая
команда, баннер, диагностические строки и `RESULT`. Если всё не помещается,
делайте два снимка с перекрытием.

`EL3EEP` длиннее одного экрана. Для M17 обязательны:

- снимок начала с `[E0]`, `[E1]` и первыми EEPROM-словами;
- последовательность снимков с перекрытием, на которой без пропусков видны все
  строки `00..3F`;
- снимок конца со словом `3F`, `[E2]` и `RESULT OK`;
- текстовый файл `M17-eeprom.txt`, вручную сверенный со снимками и содержащий
  все 64 строки без сокращения `...`.

Удобно дополнительно записать полный скролл через MAME:

```sh
MAME_3C509B_SLOT=1 tools/3com.sh \
  -aviwrite docs/evidence/stage03-YYYYMMDD-mame/M17-eeprom.avi
```

AVI дополняет, но не заменяет текстовый dump и контрольные screenshots. Если
видеозапись не работает в конкретной сборке MAME, используйте внешнюю запись
экрана и укажите средство в отчёте.

В bundle также нужны:

- `run.log` с версиями, commit, хешами, точными host/MAME/DSS-командами и
  таблицей PASS/FAIL;
- исходный `M17-eeprom.txt`;
- screenshots/видео отказов до повторного запуска;
- краткое сравнение slot 0 и slot 1: MAC, EEPROM-база и отличия полей;
- `sha256.txt` для EXE, IMG и всех файлов evidence.

Pcap для этапа 3 не нужен: сетевой обмен здесь не выполняется.

## 6. Проверка на реальном Sprinter

До подачи питания осмотрите карту, разъём и площадку `J70`. Запишите модель,
ревизию, заводской MAC с наклейки, физический slot и известную конфигурацию
base/ID-port. Не начинайте с `ISAPROBE` и не выполняйте blind scan.

Безопасная последовательность:

1. Загрузить тот же IMG и записать DSS version, хеш IMG и физический slot.
2. Выполнить `EL3INFO -v -s N -p #110 -b AUTO`.
3. Сохранить фото/скрин полного вывода до повторного запуска.
4. Сравнить MAC с наклейкой `00:20:AF:5D:69:8B`; несовпадение записать как
   наблюдение, ничего не перепрограммировать.
5. Выполнить `EL3EEP -s N -p #110`, снять весь dump `00..3F` тем же способом и
   переписать его в `H02-eeprom.txt`.
6. Только после успешного read-only обнаружения выполнить одну временную
   активацию на заранее выбранной свободной базе, например
   `EL3INFO -s N -p #110 -b #300`. Это не меняет EEPROM.
7. При timeout или неожиданном статусе прекратить тесты, сохранить вывод и
   перезагрузить DSS/машину; не переходить к сканированию портов.

Для hardware bundle нужны фотографии установки карты и её маркировки, снимки
каждого результата, полный EEPROM dump, сравнение label/EEPROM/EL3INFO MAC и
хеши использованных файлов. Сетевой кабель, pcap, TX/RX и IRQ для этапа 3 не
нужны.

## 7. Когда обновлять `specs.md`

Отмечайте только реально подтверждённые строки. MAME-пункты можно закрыть после
полной матрицы M01–M17 и сохранения bundle. Hardware-пункты — только после
реального запуска и сравнения EEPROM/MAC. Stage 2 остаётся открытым до проверки
исправленной модели MAME; feature request сам по себе его не закрывает. Stage 3
остаётся открытым, пока отсутствует хотя бы один из обязательных MAME/hardware
наборов evidence.
