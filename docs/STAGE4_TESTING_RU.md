# Этап 4: процедура проверки регистрового слоя 3C509B

Эта процедура фиксирует проверки `EL3REG` в MAME и на реальном Sprinter.
Локальные mock-тесты не заменяют ни одну из этих сред. MAME запускается без
изменения исходников эмулятора и без подключения IRQ.

## 1. Подготовка

Соберите чистый образ и запишите контрольные суммы:

```sh
make clean
make test-host package image
sha256sum build/EL3REG.EXE distr/sprinter-3c509b.img
```

Версия остаётся `0.0.1`. В IMG должны находиться `EL3REG.EXE` и `EL3REG.TXT`,
а в ZIP их быть не должно. Успешный host log обязан содержать строку о mock
`INIT/DONE x100`.

`CYCLES21` не использует CTC, `FRAMES`, RTC или turbo. Один `waitq` занимает
не менее 1 мс на 21 МГц и около 6 мс на 3,5 МГц. Максимальный CIP wait равен
100 квантам, то есть примерно 100–601 мс.

## 2. Матрица MAME

Для каждого прогона сохраните полный вывод и условия в шаблон
`docs/evidence/STAGE4_TEST_TEMPLATE.md`.

| Код | Slot | Команда | Ожидание |
|---|---:|---|---|
| R01 | 0 | `EL3REG -s 0 -p #110 -b AUTO -n 1` | snapshot и `RESULT OK` |
| R02 | 0 | `EL3REG -s 0 -p #110 -b AUTO -n 100` | `CYCLES OK=100` |
| R03 | 1 | `EL3REG -s 1 -p #110 -b AUTO -n 1` | snapshot и `RESULT OK` |
| R04 | 1 | `EL3REG -s 1 -p #110 -b AUTO -n 100` | `CYCLES OK=100` |
| R05 | 0 | `EL3REG -s 0 -p #110 -b #200` | база `0200` |
| R06 | 0 | `EL3REG -s 0 -p #110 -b #300` | база `0300` |
| R07 | 0 | `EL3REG -s 0 -p #110 -b #3E0` | база `03E0` |
| R08 | 1 | `EL3REG -s 1 -p #110 -b #200` | база `0200` |
| R09 | 1 | `EL3REG -s 1 -p #110 -b #300` | база `0300` |
| R10 | 1 | `EL3REG -s 1 -p #110 -b #3E0` | база `03E0` |
| R11 | 0 | AUTO без карты | конечный `RESULT FAIL`, управление возвращено DSS |
| R12 | 1 | AUTO без карты | то же |

Команды RX Early и TX Available передают `#07FF`, а их Window 5 readback имеет
DWORD-гранулярность и должен быть `#07FC`. Read Zero Mask должен точно читаться
как `#0096`. Любое другое расхождение сохраняйте вместе со строкой `[EV] VERIFY`;
нормализовать неизвестные значения диагностикой нельзя.

После сборки нового cycle-backend image повторите Stage 3 M01–M10. Старые
скриншоты с полем `ticks` не доказывают работу `CYCLES21`; новый вывод ошибок
использует `waitq`.

## 3. Отрицательные проверки

Проверьте без ISA-обращений:

```text
EL3REG -n 0
EL3REG -n 101
EL3REG -s 2
EL3REG -p #101
EL3REG -b #3F0
```

Каждая неверная команда должна вывести справку и `RESULT FAIL code=2`.
Mock-регрессия отдельно принудительно удерживает CIP все 100 квантов и требует
`RESULT`/status `EL3_ERR_CMD_TIMEOUT=9`, `waitq=100` и возврат управления.

## 4. Реальный Sprinter и 3C509B-TPO

До включения питания осмотрите карту и разъём. Запишите маркировку, slot,
ID-порт и планируемую базу. Начинайте с read-only `EL3INFO -v`; не выполняйте
слепой scan. Используйте только документированные порты.

После подтверждения EEPROM/MAC выполните R01–R10 для доступного slot и затем
100 циклов. При timeout или неожиданном status программа обязана закрыть
ISA-окно и вернуть управление DSS. Сохраните вывод, фото экрана или serial log,
частоту CPU, MAC, link state и длительность прогона. EEPROM не записывать.

## 5. Критерий

Stage 4 остаётся открытым, пока нет сопоставимых MAME и физических snapshot,
успешных 100 последовательных `INIT/SNAPSHOT/DONE` на реальной карте и evidence
recovery после timeout. Локальный host/mock PASS подтверждает только кодовую
часть этапа.
